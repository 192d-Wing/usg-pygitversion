# Deviations from GitVersion 6.8.2

Every intentional behavioural difference between usg-pygitversion and the
reference implementation is recorded here. If it is not listed, it is a bug.

| Area | Upstream behaviour | usg-pygitversion behaviour | Reason |
|------|--------------------|------------------------|--------|
| `/url`, `/u`, `/p` | Clones a remote into a temp dir and versions it | Rejected with a message pointing to `git clone` | Out of scope for v1 (PLAN.md section 6); avoids credential handling |
| `/updateassemblyinfo`, `/updateprojectfiles`, `/ensureassemblyinfo`, `/updatewixversionfile` | Rewrites .NET project files | Rejected with a clear error | .NET-specific; out of scope |
| Build agents | 15 agents auto-detected | GitHub Actions and GitLab CI auto-detected; generic `--output env` / `--env-file` for the rest | PLAN.md section 7 |
| Pre-release label ordering | `StringComparer.InvariantCultureIgnoreCase` (linguistic) | Case-folded code-point comparison | Python has no invariant-culture collation. Identical for the ASCII letters, digits, `-` and `.` that SemVer 2.0 permits in labels. |
| Regex dialect | .NET `Regex` | Translated to Python `re` (`usg_pygitversion/dotnet/regex.py`) | Balancing groups, `(?n)`, and `\p{...}` classes are rejected with a message naming the construct. Patterns are capped at 1024 chars; matched subjects at 4 KiB (ReDoS bound). |
| `commit-date-format` | .NET `DateTimeOffset.ToString(fmt, InvariantCulture)` | Re-implemented custom-format engine (`usg_pygitversion/dotnet/dateformat.py`) | Standard single-letter formats (`o`, `s`, `d`...) are not supported, only custom formats; GitVersion's default `yyyy-MM-dd` and all documented custom specifiers are. |
| Pre-release regex failure | Writes to the console | Logged at WARNING | Never reachable in practice; the pattern matches any string. |
| Strategy evaluation order | Order of `IVersionStrategy` registrations comes from assembly reflection (`FindAllDerivedTypes`), which follows source-file order | Fixed order: ConfiguredNextVersion, Fallback, Mainline, MergeMessage, TaggedCommit, TrackReleaseBranches, VersionInBranchName, with Fallback moved last exactly as `OrderStrategiesWithFallbackLast` does | Order only matters for ties between candidates with equal incremented versions and no source commit; no scenario or differential run has shown a difference. |
| Commit ordering | libgit2 `GIT_SORT_TIME`; `Topological \| Time`; `Topological \| Reverse` | `git log` default; `--date-order`; `--topo-order --reverse` | Equivalent orderings; commit counts and base-version selection match the reference in every differential run. |
| `ICommit.DiffPaths` | libgit2 tree diff against the first parent | `git diff-tree --no-commit-id --name-only -r --root` | Same path set; renames are reported as delete plus add in both. |
| `UncommittedChangesCount` | libgit2 diff of HEAD tree against index and working directory | `git status --porcelain --untracked-files=all --no-renames` entry count | Both count staged, modified and untracked files; verified by the dirty-flag scenarios. |
| Template formats | `{Member:format}` supports string, numeric and date formats | String formats `u`, `l`, `t`, `s`, `c` implemented; other formats fall through to the raw value | All template members are strings in practice, so numeric and date formatters never apply. |
| Unknown configuration keys | Silently ignored | Ignored, plus a WARNING naming the key | Same outcome; the warning helps catch typos (SI-10). Verified: the binary accepts `foo: bar` without complaint. |
| `/overrideconfig` value typing | Merged dictionary is re-serialised and re-read as typed YAML | Bare values are parsed as YAML scalars; quoted values stay strings | Equivalent for the supported simple-typed keys. |
| Workflow preset source | `GitFlowConfigurationBuilder` defaults when no `workflow` key is set | Vendored `GitFlow/v1.yml` (upstream's own approved serialisation of that builder) | Byte-identical to the reference `/showconfig` output; verified by test. |
| Mainline unsupported shapes | `NotImplementedException` for a main branch merged into another main branch, `Exception` for octopus merges and for an ambiguous branch point with an inheriting candidate | The same conditions raise `GitVersionError` with the upstream message text | Same behaviour, typed under the library's exception hierarchy so callers can catch it. |
| Mainline recursion depth | Merged-branch traversal recurses once per nested merge with no explicit bound | Same recursion; Python's default recursion limit (1000 frames) caps pathological nesting with a `RecursionError` instead of a stack overflow | Any real history is nowhere near the limit; the `traversed` set also guarantees each commit is visited once. |
| Usage errors | Argument parsing throws `WarningException`, which escapes as an unhandled exception (exit 134, stack trace) | Message on stderr, exit 1 | The exit code is deterministic and the message is the same; a crash was never intended behaviour. |
| Out-of-scope switches | `/updateassemblyinfo`, `/ensureassemblyinfo`, `/updateprojectfiles`, `/updatewixversionfile`, `/url`, `/dynamicRepoLocation`, `/u`, `/p` | Rejected with a message naming the feature as out of scope | PLAN.md section 1; the switches are recognised so a typo is not mistaken for a target path. |
| Repository normalisation on build servers | `GitPreparer` creates local branches from remote-tracking ones, may fetch, and checks out the agent's branch | Read-only: the agent's branch is resolved against local and remote-tracking branches; the "exactly one remote" check is kept; nothing is written to the repository | The tool never mutates the user's repository (CM-5); `/nonormalize` still disables the check. Detached CI checkouts resolve correctly because remote-tracking branches are candidates. |
| Handled-error output | Whole log is dumped to stdout on failure | The message is written to stderr once; the log file/console appender records it at info level | Keeps stdout clean for `eval` and JSON consumers. |
| `/output dotenv` quoting | `GitVersion_<Name>='<value>'` with the value unescaped | Same shape, but the value is POSIX single-quoted (`'` becomes `'\''`) | A branch named `x'$(id)'y` would run `id` when the file is sourced; SECURITY.md puts code execution from branch names in scope. Byte-identical for every value without a single quote (SI-10). |
| Cache key inputs | refs, config, HEAD name and tip, override document | The same, plus the requested target branch (`/b`, `GITVERSION_BRANCH`, build agent) and commit (`/c`) when set | Upstream checks the target branch out before calculating; this port is read-only, so without them a cached HEAD result would be served for `/c` or `/b` (SI-7). Keys without `/b` and `/c` are unchanged. |
| Revision arguments to git | libgit2 API, no argv | Every revision is preceded by `--end-of-options`; `/c` rejects a leading `-` | Prevents a value such as `--output=<file>` from being parsed as a `git log` option. Requires git 2.24 or newer (SI-10). |
| Regex with nested unbounded quantifiers | Compiled and matched; .NET has a `MatchTimeout` that GitVersion does not set | Rejected at compile time when an unbounded quantifier is applied to a group that itself starts with an unbounded quantifier, e.g. `(a+)+` | Python's `re` cannot be interrupted, so a hostile `GitVersion.yml` could hang a build; upstream's own default patterns all pass (SI-10). |
| `{env:NAME}` in configuration templates | Reads any environment variable | `label` and `assembly-*-format` templates see an environment with credential-looking names withheld (`secret`, `token`, `password`, `credential`, `private`, `api_key`, `access_key`, `auth`, `cookie`, `session`, case-insensitive); withheld names are logged at DEBUG; `/format` on the command line still sees everything | A PR that edits `GitVersion.yml` must not be able to copy a CI secret into the version string, `$GITHUB_ENV` or the logs, where the `u`/`l` formats would also defeat log masking (SC-28). |
| Cache key directory order | `.git/refs` is enumerated in filesystem order | Sorted enumeration | Keys are deterministic across filesystems; cache files written by the .NET tool are simply not reused. |
| Console log line format | `LEVEL [yy-MM-dd HH:mm:ss:ff]` on stdout for `/output buildserver` and `/l console` | Same format on stdout in those modes; otherwise warnings and errors go to stderr as `LEVEL: message` | Upstream writes nothing at all outside those modes; stderr warnings are additive. |
| `--output env`, `--shell`, `--prefix`, `--env-file`, `GITVERSION_BRANCH` | Not present | Additions from PLAN.md section 7.5 | Cover build servers without a dedicated agent. |
| Package version | Static `version.json`/GitVersion at build | `hatch_build.py` runs the tool on its own repository and maps `SemVer` to PEP 440 (`_pep440.py`) | Dogfooding; mapping table documented in the module. |
